# Publish a blog post to sajeeshnair.com

Use when Sajeesh says "publish <note>" or gives a path to an Obsidian note.

## Where things live
- Source notes: Obsidian vault on his Mac (vault root `/Users/sajeeshn/Obsidian-Notes/Cerebro`), `/Users/sajeeshn/Obsidian-Notes/Cerebro/Areas/Startups-Product -Engineering-Leadership/ramblings/` (a `publish/` subfolder if he sets one up). Reading them needs a Remote Control session on his Mac ("MacBook-Pro", folder `~/Obsidian-Notes/Cerebro`). Pass his own words along; the Mac refuses to push on a relayed request alone.
- Site: github.com/sajeesh10/sajeeshnair.com, branch `main`. Plain HTML/CSS generated by `build.py`; posts in `content/posts/`. Pushing to main auto-deploys on Netlify (publish dir `public`).

## Steps
1. Read the note. If only a name is given, find it in the ramblings folder.
2. `git pull origin main` first. Other sessions push to main too.
3. Create the post in `content/posts/` following an existing post's header format:
   - title from the file name (keep his casing unless he asks otherwise)
   - `date:` a random earlier day of the current month, never a future date, even when several posts go out on the same day
   - `topic:` one or more tags, comma-separated (e.g. `Leadership, Sales`). Existing tags: Leadership, 0 to 1, Sales, Performance engineering, Cloud. Pick the ones that fit and say which you picked.
   - no `archive: yes` (that is only for the old 2014-2018 technical posts).
4. Copy the body **verbatim**. Never edit his words. Drop bits that are not part of the essay and say so in the reply: a leading `Date: …` line, a trailing `---`/`-----`, pasted file names. If his request asks for something specific (link an earlier post, fix bullet nesting), do exactly that and nothing more. After building, check that the rendered body matches the source text exactly.
5. Run `build.py`, check the page renders in light and dark mode, then commit and push to main.
6. Reply with the live URL (https://sajeeshnair.com/posts/<slug>/) and a short, numbered list of optional suggestions (typos, title case, headings, closing line). Do not apply them.
7. If he replies with numbers ("fix 3, 4, 5", or partial picks like "3 - RunWhen only", "4 - skip"), apply only those items. If he says "apply all", apply every item. Pull, build, and push again, then offer to apply the same edits to the Obsidian note and do it if he says yes.

## Post footer
build.py adds "Written by a human. Expect the odd typo and grammar slip." to every post. Don't add it to the markdown.

## Republish
When he says he edited a note and wants it republished: re-read the file, replace the post body verbatim (keep date and tags unless told otherwise), list what changed, pull, build, and push.

## Don'ts
- No diagrams or banners unless he asks. He turned down auto-generated ones.
- Don't add intro text, summaries or headings of your own.
